# 关于本项目

## 项目目标

实现从 Markdown 文档到公开网站的自动化发布：写完 `.md` 文件，`git push` 一次，网站自动更新，不再手工上传文件，也不再依赖本地环境是否能跑起来。

## 技术组成

| 工具 | 作用 |
| --- | --- |
| Markdown | 编写文档内容 |
| MkDocs Material | 将文档构建成静态网站 |
| GitHub Actions | 自动执行安装、构建和部署 |
| GitHub Pages | 托管并提供网站访问地址 |

## 实践体会

以前我理解的"部署"是把打好的包上传到服务器，再用某种方式重启服务。这次发现对静态站点来说，部署可以简化成两步：把构建产物作为 artifact 上传，再交给 Pages 托管。理解了这一点之后，`build` 和 `deploy` 为什么要拆成两个 job 也就顺了——构建失败时不应该去动线上环境，构建和发布应该分开失败、分开重试。

另外一点体会是 `mkdocs build --strict` 的价值。本地不加 `--strict` 时，断链、缺失的页面引用只会打印警告然后继续构建；一旦开了严格模式，这些问题会直接让构建失败，而工作流里用的正是严格模式，所以本地必须先过一遍，否则推上去就是一片红色。
